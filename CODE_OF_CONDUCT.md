# Code of Conduct

## Our Pledge

PacketSnitch is an open-source project that welcomes contributors from all backgrounds and skill levels. We are committed to providing a respectful, inclusive, and harassment-free environment for everyone.

## Our Standards

### Expected Behavior

- **Be respectful** — Treat others with kindness, empathy, and professionalism.
- **Assume good intent** — Miscommunications happen. Seek to understand before being critical.
- **Give constructive feedback** — Critique the work, not the person. Offer solutions, not just complaints.
- **Acknowledge different perspectives** — Diversity of thought strengthens the project.
- **Take responsibility** — If you make a mistake, own it and learn from it.
- **Focus on what matters** — Keep discussions relevant to the project and productive.

### Unacceptable Behavior

- Hate speech, racism, sexism, homophobia, transphobia, or any form of discrimination.
- Personal attacks, trolling, or sustained disruption of discussions.
- Harassment of any kind — public or private.
- Publishing others' private information without explicit permission.
- Any conduct that would be unacceptable in a professional workplace.

**Don't be an asshole.** If you wouldn't say it in a professional workplace, don't say it here. Your contributions will be rejected and you may be banned from participating.

## Where Does This Apply?

This Code of Conduct applies to all PacketSnitch spaces, including:

- GitHub Issues and Pull Requests
- Wiki pages and documentation
- Discord, IRC, or other community channels
- Any public or private communication related to PacketSnitch

## Dos and Don'ts

### GitHub Issues

| Do | Don't |
| ---- | ------- |
| Search existing issues before opening a new one | Duplicate issues without adding new information |
| Provide clear steps to reproduce bugs | Vague "it doesn't work" reports |
| Include version numbers, OS, and relevant logs | Posting sensitive data or credentials in issues |
| Be patient — maintainers volunteer their time | Demanding instant responses |
| Use the issue templates when available | Ignoring the template structure |

### Pull Requests

| Do | Don't |
| ---- | ------- |
| Keep PRs focused and minimal | Submit massive, unrelated refactors |
| Describe *why* the change is needed | Just "fixed it" or "updated stuff" |
| Reference related issues (e.g., "Closes #123") | Leaving PR description blank |
| Respond to review feedback constructively | Getting defensive about legitimate critique |
| Test locally before opening a PR | Pushing broken code and hoping for the best |

### Wiki and Documentation

| Do | Don't |
| ---- | ------- |
| Use clear, concise language | Overly complex jargon without explanation |
| Follow existing formatting conventions | Rewriting entire pages for style preferences |
| Add useful context and examples | Removing information others may need |
| Correct errors respectfully | Mass-deleting content without discussion |

### General Community

| Do | Don't |
| ---- | ------- |
| Welcome new contributors | Gatekeeping or "read the source" dismissals |
| Answer questions you know the answer to | Demeaning others for not knowing something |
| Share knowledge and teach | Hoarding information to feel superior |
| Report violations to maintainers privately | Publicly shaming individuals |
| Suggest improvements constructively | Name-calling or ridiculing ideas |

## Enforcement

Violations of this Code of Conduct may result in:

1. **Private warning** — A maintainer contacts you to explain the issue.
2. **Temporary suspension** — Your access to issues/PRs is restricted temporarily.
3. **Permanent ban** — Your contributions are rejected and you may not participate in PacketSnitch spaces.

The project maintainer, Marshall Whittaker (`oxagast`), has final say on enforcement.

## Reporting

If you witness or experience unacceptable behavior:

- **Private issues:** Email <bugs@packetsnitch.com> or <support@packetsnitch.com>
- **GitHub:** Use the "Report abuse" link on any comment or issue.

All reports are treated confidentially. We will not publish your identity without your explicit consent.
